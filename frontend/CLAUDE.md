# frontend — 開発方針

## CSS装飾タスクのルール（重要）

CSS装飾（スタイリング）作業では、原則として **装飾のみに徹する**。

### やること
- 既存要素の見た目を整える：余白・幅・配色・タイポグラフィ・レイアウト（flex/grid）・角丸・影・状態表示（hover/focus 等）
- `className` の追加・調整を中心に行う
- 全画面共通のトークン/ユーティリティ（`app-container` / `brand-gradient` / `brand-tile` など）を活用する

### やらないこと（装飾タスクでは変更しない）
- ロジック：データ取得・API呼び出し・認証フロー・状態管理（useState 等）・条件分岐
- リンク先（`href`）の変更、要素の追加・削除
- 表示文言（テキスト）の変更
- 既存の DOM 構造（`<div>` / `<ul>` / `<li>` など）の意味的な組み替え

> 例外：トップ/ログイン画面（`app/page.tsx`）は初回のみ UI 改善込みで再設計済み。
> それ以降の画面は上記「装飾のみ」ルールに従う。

## ブランド仕様（LiveQA）

- プライマリ：スカイブルー（アイコン/ロゴ地色）
- アクセント：ゴールド（下線・波形）＝ 投票・ライブ感の強調に使用
- 形状：角丸大きめ・親しみやすい（`--radius: 0.75rem`）
- 配色トークンは `app/globals.css` の `:root` / `.dark` に定義（light/dark 両対応）

## スクリーンショットの運用（重要）

画面（UI）を作成・変更したら、**その都度スクリーンショットを撮ってユーザーに送信する**。

- 対象：画面の見た目が変わる変更（新規実装・装飾・レイアウト調整など）
- 手順：ビルドで確認 → 実際に描画してキャプチャ → ユーザーへ送信 → コミット
- 認証やAPIが必要でそのまま描画できない画面は、一時的なプレビュー用ルートにモックデータを流して撮影し、**確認後にそのプレビューは削除**する（リポジトリには残さない）
- ローカルサーバはポート競合に注意（起動前に既存の next プロセスを停止）

## 優先方針

- 画面幅は **PC優先**（`lg:` 以上を基準に、モバイルは縮退で対応）
- shadcn/ui（base-luma / remixicon）の既存部品を活用する
