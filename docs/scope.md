# スコープ（MVP-A / MVP-B）

30日で3名が確実に完走できるよう、コミットラインを **MVP-A（必須）** とし、余力で **MVP-B（ストレッチ）** に進む。

## MVP-A（必須・コミットライン）

### セキュリティ関連

- 会員登録 / ログイン / ログアウト（Cookieセッション + Redis）
- RBAC（一般会員 / 運営管理者）
- CSRF保護の有効化（stateful化に伴い、前回のstateless JWTとは逆に有効化する）
- WebSocketハンドシェイクのCookie認証

### WebSocket

- 入札のリアルタイム反映（現在価格・最高入札者・残り時間カウントダウン）
- 入札の同時実行制御（楽観ロック / 悲観ロックで価格の整合性を担保）

### その他主要CRUD

- 出品（商品CRUD・画像1枚）
- 商品一覧・詳細（SSR）
- 動的検索（カテゴリ / 価格帯 / キーワード・QueryDSL）
- 入札
- カテゴリ参照
- マイページ（自分の出品・入札）

### 締切→落札確定

- MVP-Aではオンデマンド / 手動（締切超過を検知した時点で確定）。自動化は MVP-B の Spring Batch で対応する

### 基盤

- Docker一括起動（`nextjs` / `api` / `postgres` / `redis`）
- GitHub Actions CI

## MVP-B（ストレッチ・余力があれば）

- **Spring Batch**: オークション自動締切 → 落札確定 → 通知、日次売上・人気ランキング集計、CSVエクスポート
- **ページング等**: サーバーサイドページング、並び替え / 締切間近フィルタなど検索条件の拡張
- ウォッチリスト・リアルタイム通知
- 運営モデレーション・通報
- 即決価格
- GitHub Actions CD（デプロイ）

## 対象外

- 決済連携
- 配送・住所管理
- レビュー・評価
- チャット
- モバイルアプリ
- 複数画像・画像加工

## 削る順番（時間不足時・MVP-B内）

1. 運営モデレーション
2. 集計・ランキング / CSV
3. 通知
4. ウォッチリスト
5. 自動締切バッチ（手動締切で代替）

**入札コア（WebSocket）とセキュリティは最後まで死守する。**
